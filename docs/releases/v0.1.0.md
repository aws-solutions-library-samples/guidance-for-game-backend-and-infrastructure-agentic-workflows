# v0.1.0

`v0.1.0` is the first immutable, read-only baseline of Game Agent, a Guidance for game backend and infrastructure operations built on Amazon Bedrock AgentCore. It records an accepted `main` source state. Creating the tag or the GitHub Release deploys nothing.

Release commit: TBD at freeze. Deployed-validation evidence: TBD at freeze (#770).

## Defaults

The default deployment, run with `scripts/deploy.sh`, creates:

- an Amazon Bedrock AgentCore Runtime for the backend. The orchestrator uses Claude Haiku 5.5 and the specialists use Claude Sonnet 5.5, both through their `global.` system inference profiles. The runtime platform version defaults to **V1** (`GBAW_AGENTCORE_PLATFORM_VERSION`);
- Amazon Cognito authentication, Amazon Bedrock Guardrails, and managed prompts published to Amazon Bedrock Prompt Management;
- three Amazon Bedrock Knowledge Bases, one each for GameLift, EKS and Cost, with seeded source documents;
- a table that stores validated, time-limited cost-report snapshots, plus observability resources;
- when Docker is available, the Next.js frontend on Amazon ECS Express with its WAF and security resources.

By default, the chat runtime is **provider-read-only**: it has no GameLift, EKS or Cost write permissions. The operations control plane is off by default (`GBAW_OPERATIONS_MODE=disabled`), and the default deployment creates no operations API, executor, public MCP facade or AgentCore Gateway. The source-control connector and EKS cluster enrollment are both optional and disabled by default.

## Capabilities

- **GameLift:** read-only fleet, capacity, utilization and scaling-policy questions, answered through scoped AWS SDK tools.
- **EKS:** read-only cluster questions through the AWS API and EKS MCP servers. Optional cluster enrollment keeps Kubernetes secrets and mutating verbs excluded.
- **Cost:** spend reports rendered from validated Cost Explorer snapshots, so monetary figures never come from model-written prose, plus cost-optimization guidance.
- **Knowledge Base retrieval** for each specialist, and **AgentCore Memory** keyed by a pseudonymous actor ID.
- **Chat:** an authenticated web UI. Access tokens are verified at both the frontend proxy and the runtime.

As the first release, this has no previous tag to compare against.

## Known issues

These are open, release-relevant issues. Each P1 below carries a waiver for this release, with the named owner TBD at freeze.

- **#734 (P1, waived):** on AgentCore Runtime V2, the EKS MCP client can time out starting in a freshly restored instance. This release defaults to V1, which is not affected. Moving the default to V2 is tracked there.
- **#586 (P1, waived):** AgentCore Evaluations integration is planned and not part of this release.
- **#775:** where VPC Block Public Access is enabled (`block-ingress` or `block-bidirectional`), the frontend cannot be deployed without an account owner's exclusion for its VPC or subnets. The frontend uses public subnets in the default VPC and an internet-facing load balancer. See the deployment prerequisites. The backend and Knowledge Bases are unaffected.
- **#602:** for GameLift container fleets, the assistant lists the fleet and its configuration, but it cannot report live capacity or utilization.
- **#604:** memory recall can describe a stored game-session length as the age of the current chat.
- **#783:** EKS questions can take about 100 seconds end to end. That is inside the request budgets, but noticeably slower than GameLift and Cost questions.
- **#782:** the runtime evaluates the Guardrail's working `DRAFT` version rather than a pinned published version.
- **#744:** dev-only test and lint dependencies carry moderate and low advisories that are not yet fixable upstream. They are not in the production image.

## Compatibility

This is a pre-1.0 release (`v0.x`): there is no stability guarantee for configuration, environment variables or behavior between minor versions, and breaking changes are possible before `v1.0.0`. Validated Region: TBD at freeze, from the evidence comment. The cost examples in the README use US West (Oregon). Models: Claude Haiku 5.5 and Claude Sonnet 5.5, through `global.` system inference profiles only; application inference profiles over these models are not supported yet. Backend: Python 3.13.

## Deployment

1. Check out this exact tag: `git checkout v0.1.0`.
2. Follow `docs/DEPLOYMENT_GUIDE.md` and run `scripts/deploy.sh`. On Windows, use the PowerShell `Deploy-GameAgent` command.
3. Verify the deployment with the read-only `scripts/infrastructure/check-deployment.sh` and `validate-deployment.sh`.

Creating the tag or the release does not deploy anything.

## Rollback

Rollback means redeploying a known-good tagged source:

1. Check out the tag: `git checkout v0.1.0`.
2. Redeploy it with `scripts/deploy.sh`.
3. Record the rollback and its reason on the relevant issue.

No emergency-disable mechanism is deployed by default; an operations kill switch is only planned. `release-manifest.json` for this tag lets you confirm the dependency-lock, prompt-source and infrastructure-template hashes. See `docs/RELEASING.md`.
